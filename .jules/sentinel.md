## 2026-03-05 - [Tailored CSP for WebGL & Canvas Heavy Static Next.js Applications]
**Vulnerability:** The portfolio application lacked any HTTP security headers (specifically Content Security Policy, X-Frame-Options, and Strict-Transport-Security), exposing the client to potential Clickjacking, MIME-type sniffing, and Cross-Site Scripting (XSS) attacks.
**Learning:** Next.js static / hybrid pages that rely on React Three Fiber (R3F) and animation frameworks (such as GSAP and Framer Motion) utilize inline styles and dynamic WebGL shaders/web-workers compiled from Blob URLs. Implementing a generic, overly-restrictive CSP blocks WebGL canvas initialization and shader execution. Therefore, a secure yet highly-tailored CSP must explicitly allow `blob:` under `worker-src` and `img-src` to facilitate client-side rendering of WebGL and 3D scenes.
**Prevention:** Always integrate standard defense-in-depth headers on Next.js deployment levels via `next.config.mjs`. For R3F/3D canvas sites, craft a customized CSP allowing `default-src 'self'`, `script-src 'self' 'unsafe-inline' 'unsafe-eval'`, `style-src 'self' 'unsafe-inline'`, `img-src 'self' data: blob:`, and `worker-src 'self' blob:`. This ensures robust browser-level defenses without degrading interactive 3D capabilities.
